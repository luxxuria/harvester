# Harvester

Весь нейрокод был полностью переписан руками, с целью чему-то научиться и вместе с этим решить актуальные проблемы.
Скрипт стал юзать меньше процессорного времени за счет уменьшения спавна ядер xray и других оптимизаций, так же были убраны лишние буферы и векторы жрущие память.
Пайплайн стал более линейным, код читаемым, добавлено больше контекста для ошибок. В будущем, возможно, конфиги в xray будут обновляться через grpc вместо перезапусков.

## Файлы с прокси

Скрипт обновляет 3 файла:

### 1. ping_tested.txt
В этом списке лежат все прокси которые ответили на tcp ping и вернули свое ip через ядро. Комментарии никак не модифицируются, uri складываются как есть.

### 2. speed_tested.txt
Основной список в котором лежат прокси которые смогли скачать тестовый файл со скоростью не меньше 48 мбит/с. Перед этим делается запрос к `api.ipify.org` и `ifconfig.me/ip` чтобы получить ip сервера. 
По ip через maxminddb берется iso code и хостер. В комментарий uri добавляется флаг страны, скорость и очищенное имя хостера.

### 3. non_ru.txt
Копия `speed_tested.txt` с вырезанными российскими локациями.


## Как происходит сбор
В самом начале из `nodes.txt` берутся ссылки на листы с прокси. Они параллельно собираются и дедуплицируются с помощью хеширования uuid, host, port через xxh3, а затем вставку в `DashMap`. Хеш передается напрямую, так что повторного хеширования не происходит. В параметрах vless убираются различные вариации `AllowInsecure`, `raw` заменяется на `tcp`.
С помощью buffer_unordered спавнятся 150 изолированных футур, каждая берет себе свободный порт из `ArrayQueue` и в конце его возвращает. В начале тестирования происходит попытка подключится к порту сервера, в случае успеха создается конфиг xray, поднимается ядро, и через stdin принимает этот конфиг. После ожидания порта отправляются два параллельных запроса к ipify и ifconfig. Как только один из запросов успешен, другой отбрасывается и ip парсится в IpAddr. Далее у семафора берется permit и начинается замер скорости.
